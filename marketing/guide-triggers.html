Automations / Triggers

Triggers

Triggers decide when an automation runs. A script can carry up to five triggers, and at most one of each non-manual type — so a single automation might run from the palette, when a matching page loads, and again on a daily schedule. There are six trigger types in all.

Before you arm anything

Imported automations arrive with every non-manual trigger disarmed. They won't fire on their own until you open the automation in the builder and explicitly arm them. Manual triggers always run on demand.

manual

Runs when you select the automation from the palette or press its keybinding. The bread-and-butter trigger for one-off tasks, form filling, and data extraction.

A manual trigger can also define a parameter form — a set of text, textarea, and select fields. When you run the automation, the palette shows that form first, and your answers land in {{params.fieldId}} variables you can interpolate into steps. 

{
  "type": "manual",
  "parameters": [
    { id: "query", label: "Search for", type: "text", required: true },
    { id: "lang",  label: "Language",   type: "select", options: [
      { value: "en", label: "English" },
      { value: "es", label: "Spanish" }
    ]}
  ]
}

urlMatch

Fires when a page within the script's scope loads, or when a single-page-app navigation happens inside it.

FieldDefaultWhat it does
on: ["load", "spa"] both Fire on a full page load, an SPA navigation, or both.
oncePerPage true Only fire once per page; resets on a real navigation.
delayMs 0 Wait 0–10000 ms before firing — useful for pages that render dynamically. 
{
  "type": "urlMatch",
  "on": ["load", "spa"],
  "oncePerPage": true,
  "delayMs": 1000
}

elementAppears

Fires when a DOM element matching a selector first appears on an allowed page — handy for content that loads late.

FieldDefaultWhat it does
selector — CSS- or text-based selector for the element to watch.
oncePerPage true Only fire once per page.
throttleMs 1000 Minimum 250–60000 ms between fires — an observer-storm guard.

Auto-dismiss cookie banners Auto-hide ads 

{
  "type": "elementAppears",
  "selector": { strategy: "text", value: "Accept all" },
  "oncePerPage": true,
  "throttleMs": 250
}

interval

Runs every N minutes using chrome.alarms. The browser wakes the extension on the interval, finds the first open tab matching the script's urlRules, and runs there; if no tab matches, the run is skipped.

  • everyMinutes — 1 to 10080 (one minute up to seven days).
Firefox note

The interval trigger requires the tabs permission on Firefox.

{
  "type": "interval",
  "everyMinutes": 30
}

schedule

Runs daily at a specific local time, re-arming itself each day. It uses the same tab-matching behavior as interval: it finds the first open tab matching the script's scope, and skips if none is found.

  • at: "HH:MM" — 24-hour format, in your browser's local time.
{
  "type": "schedule",
  "at": "09:00"
}

onStartup

Runs when the browser starts.

Open your daily dashboard Run maintenance 

{
  "type": "onStartup"
}

Scope governs where they act

A trigger decides when an automation runs; the script's scope — its URL allow/deny rules — governs which pages a trigger is allowed to act on. A urlMatch or elementAppears trigger only fires on pages within scope, and interval and schedule look for a matching tab before running. See Variables & selectors for how to target elements, and Steps & operations for what runs once a trigger fires.
