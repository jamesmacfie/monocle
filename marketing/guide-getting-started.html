Getting started with automations

Automations let you capture a repetitive web task once and replay it on a keystroke, a page load, or a schedule. This guide takes you from zero to a working automation, then on to the full reference. No programming required — automations are declarative documents, not code.

What you'll need

Just Monocle, installed in Chrome or Firefox. Everything happens in the extension's options page — there's nothing to install, no account, and no server.

Open the builder

  1. Open the palette with ⌘⇧K and run Monocle Settings (or right-click the extension icon → Options).
  2. Go to the Automations section.
  3. Click Add Examples to drop in a set of curated automations covering every trigger type and most of the step vocabulary — the fastest way to see what's possible.
Tip

Every automation you create also becomes a palette command (userscript-<id>), so you can run it by name from anywhere — and give it a keybinding later.

The mental model in one minute

An automation is a stored document with four moving parts. Keep these in mind and the rest of the guide falls into place:

  • Triggers — when it runs (manually, on a matching page, when an element appears, on an interval, on a schedule, at startup).
  • Scope — the URL allow/deny rules that decide which pages it's allowed to touch.
  • Variables — named values: fixed literals, references to snippets, or runtime values captured during the run.
  • Steps — the work: page actions like click and fill, engine ops like navigate and clipboard, and control flow like branch and loops.

Build your first automation

Let's auto-fill a development login. Create a new automation and give it a name, an icon, and a scope so it only runs where it should. 

name:    "Dev login"
icon:    LogIn
scope:   allowUrls: ["dev.example.com"]
trigger: manual

1. Store the credentials as variables

Keep the username and password in snippets, then reference them from the automation. Snippet-backed variables are resolved in the background and never logged. 

vars:
  user: { kind: "snippet", snippetId: "dev-username" }
  pass: { kind: "snippet", snippetId: "dev-password" }

2. Add the steps

Fill the two fields, click the button, wait for the dashboard, and confirm with a toast. The {{user}} and {{pass}} templates are expanded before the page ever sees them. 

steps:
  - fill   { target: "#username", text: "{{user}}" }
  - fill   { target: "#password", text: "{{pass}}" }
  - click  { target: text "Sign in" }
  - wait   { for: { urlIncludes: "dashboard" }, timeoutMs: 5000 }
  - toast  { level: "success", message: "Logged in" }

3. Test it

Open the dev site, then use Test on Active Tab in the builder to run the automation and see a per-step outcome list. Fix any selector that didn't match, and you're done.

4. Give it a shortcut (optional)

In Monocle's keyboard settings, bind this automation's command to a shortcut like CtrlShiftL. A non-shift modifier is required so the binding still fires while a form field is focused.
