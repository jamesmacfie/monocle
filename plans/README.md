## Findings considered and rejected

Recorded so nobody re-audits them:

Round 1:

- **"Debounced search lands on the wrong page after navigation"**: false —
  the search effect's cleanup cancels the pending timer when
  `currentPageId` changes, and the slice guards stale responses by `seq`.
- **"`ignoreSearchUpdate` flag leaks after failed navigation"**: false — the
  flag is only set on the success path (`_clearAndResetSearch`) and is
  consumed-and-reset by the next `updateSearchValue` call.
- **"NewTab palette never loads settings/permissions"**: false —
  `newtab/NewTabApp.tsx:45-46` dispatches both at app level.
- **"Shared `lastRootSearch` narrowing cache returns wrong results across
  tabs"**: by design — the base-array identity check forces a full rescan on
  any mismatch; worst case is a wasted rescan, never a wrong result.
- **"pendingSingle chord timeout leaks sequence state on error"**: false —
  the `finally` block in `schedulePendingSingle` always resets.
- **"Keystroke handler adds 50–100ms typing latency"**: overstated — the
  handler is async and doesn't block typing; the real cost (per-keystroke
  message) is plan 003.
- **Module-level `validationRateLimit` resets on worker restart**: accepted —
  defense-in-depth; restart-reset is consistent with its purpose.
- **Sequence state lost on worker restart mid-sequence**: accepted as benign
  — the 800ms chord timeout already exceeds any restart gap by design.
- **keybindingTemplates.ts as JSON asset / file-per-command splitting of new
  shortcut files**: style preferences without concrete cost.

Round 2:

- **"`isEditableElement` has no early exits, evaluates all 15+ checks per
  keystroke"**: false — the function returns early at every tier
  (`event-filter.ts:73-130`: tag name, contenteditable, inputmode, role,
  each editor-library check).
- **"Async properties (name/description/icon) re-resolved per keystroke in
  `commandsToSuggestions` duplicate index-time work"**: largely by design —
  state-aware labels (e.g. Pin/Unpin) MUST re-resolve at suggestion time
  with fresh context; static values resolve trivially; conversion runs only
  on the returned top-N, and the index pre-tokenizes match fields. Caching
  resolved props would trade correctness for little.
- **"`getVisibleEntries` re-filters all entries per keystroke" /
  "usage ranking pays a storage read per keystroke"**: false — both are
  already memoized (`visibleCache` keyed by index+url, `cachedUsageRank`
  with TTL + targeted `monocle-commandUsage` invalidation).
- **List virtualization for search results**: rejected for now — the
  background caps results at ~40-50 rows and virtualization risks cmdk's
  keyboard navigation; revisit only if the cap rises (noted in plan 010).
- **Fine-grained (per-source) index invalidation/rebuild**: rejected for
  now — high complexity, HIGH risk; plan 008's event filtering + SWR should
  capture most of the win. Revisit with profiling evidence.
- **Dual window+document capture listeners in `robust-key-capture.ts`**: by
  design for robustness; the WeakSet dedup makes the second invocation a
  no-op. Cost is one Set lookup per keystroke.
- **"RobustKeyCapture install lacks a double-install guard"**: false — the
  guard exists at `robust-key-capture.ts:54` per the auditor's own
  follow-up.

## What was and wasn't audited

Round 1: deep audit (8 parallel auditors) covering correctness (background +
UI), performance (background + UI), tech debt/simplicity (background +
UI/shared), test coverage, MV3 lifecycle reliability, and the uncommitted
in-flight work. Round 2: focused performance audit (2 auditors + direct
reads) of the search pipeline (index build/invalidation, child-page search,
scoring, suggestion conversion, list rendering) and the keybinding pipeline
(capture, registry build, sequence evaluation, execution).

**Not audited**: security beyond what surfaced incidentally (the site SDK
threat model has its own doc), dependencies & migrations, docs accuracy, DX
tooling, and product direction. `server/`, `docs/`, and `.codex/` were
excluded. No profiling was run — all quantification is from code structure;
plans note where profiling should gate further work.
