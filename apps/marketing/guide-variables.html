Automations / Variables & selectors

Variables & selectors

Variables give an automation its data; selectors give it its targets. Interpolation expands variables into a step's fields in the background, before the page ever runs — so the page only ever sees finished values, and the parts that address the page stay fixed and reviewable.

The three kinds of variable

A variable is a named value declared in the automation's vars block. There are three kinds, distinguished by where the value comes from.

Literal

A fixed string baked into the document.

vars:
  companyName: { kind: "literal", value: "Acme Corp" }

Snippet

References a saved snippet by id. The snippet body is resolved and its placeholders are interpolated at run time, in the background. Use this for credentials and any multi-use text you'd rather keep in one place. 

vars:
  loginEmail: { kind: "snippet", snippetId: "abc123" }

Runtime

Set during the run by a getText or setVariable step. Declared empty; filled with live page data as the automation executes. 

vars:
  confirmationCode: { kind: "runtime" }

Template syntax

Interpolatable fields — such as fill.text, setVariable.value, toast.message, and navigate.url — use {{…}} templates. The engine expands them in the background before the step is dispatched.

  • {{varName}} — a declared variable.
  • {{trigger.type}}, {{trigger.url}}, {{trigger.matchedText}} — the fire context that started the run.
  • {{params.fieldId}} — an input from a manual trigger's form (if the automation defines parameters).
  • {{snippet:snippetId}} — an inline snippet reference.
  • {{index}}, {{item}} — loop scope inside a forEach body ({{item}} is the current element's text; {{index}} is the 0-based iteration).

Page-context placeholders

Templates may also use snippet placeholders, resolved by the engine from the current page and clock. These are the same placeholders the Snippets feature uses.

Placeholder Expands to
{url} The current page's full URL.
{title} The current page's title.
{domain} The page's host (domain).
{path} The URL path.
{uuid} A freshly generated UUID.
{timestamp} The current timestamp.
{date:FORMAT} The current date, formatted by FORMAT.
{i} A persisted counter, shared with palette snippet insertion.

Pipes

A template value can chain a fixed set of transforms with the | operator. Pipes apply left to right, take literal arguments, and run no flags. 

"Search for: {{params.query | upper | slice:0:50 | encodeUriComponent}}"
trim — strip surrounding whitespace upper — uppercase lower — lowercase slice:a:b — substring by index replace:from:to — first match only encodeUriComponent — URL-safe encoding length — string length

What is never interpolated

Selectors, CSS bodies, and URL patterns are never templated

These fields are addresses, not data. They are never run through {{…}} interpolation, so they stay fixed and fully reviewable in an import summary. A templated selector would be impossible to review — you couldn't tell what an automation actually touches — so the boundary is deliberate and hard.

Selectors

Every step that targets an element uses a selector. There are two strategies. A selector's optional index picks the Nth match (0-based); omitting it means the first match.

CSS

Queries the page with querySelectorAll. An invalid CSS selector throws an error. 

{ "strategy": "css", "value": "#username", "index": 0 }

Text

Walks the DOM tree matching an element's text content. exact: false (the default) matches a substring; exact: true requires the full text to match. Whitespace-only and hidden elements are skipped. within scopes the search to a subtree, and index picks the Nth match after filtering. 

{
  "strategy": "text",
  "value": "Sign in",
  "exact": false,
  "within": { "strategy": "css", "value": "form#login" },
  "index": 0
}
