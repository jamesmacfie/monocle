Privacy policy

Local by default. Explicit when data moves.

Monocle has no account system, advertising SDK, or analytics collector. Most data stays in the browser profile. Optional integrations can move specific data outside the extension, and this page names each boundary.

Effective: 17 July 2026

Publisher: James Macfie

Applies to: the Monocle browser extension and this static website.

Short version

  • Monocle does not sell personal data and does not use data for advertising or profiling.
  • Settings, snippets, automations, favorites, and usage ranking are stored in the local browser profile.
  • There is no Monocle-operated cloud service or user account.
  • Built-in photo and favicon features make limited third-party requests.
  • Outbound automations, OpenAI generation, Native Bridge, and peer-extension commands are optional and separately enabled.

Data stored in the browser

Monocle stores command settings, URL rules, keybindings, favorites, local command-usage counts, snippets, automation documents, feature configuration, feature runtime state, and temporary surfaces in the browser's local extension storage. It does not use browser sync storage.

This data remains until the user removes it through Monocle, clears the extension's storage, or uninstalls the extension. Anyone with access to the browser profile may be able to access locally stored data. Personal API keys and automation credentials should be treated accordingly.

Built-in remote requests

Unsplash backgrounds

When the new-tab background feature is active, Monocle requests photo metadata from api.unsplash.com and loads the selected image. Monocle does not add page content, snippets, or palette queries to that request. Unsplash and the image host still receive ordinary network metadata such as the user's IP address and user agent.

DuckDuckGo favicons

Bookmark and history rows may request a favicon from icons.duckduckgo.com. The requested domain and ordinary network metadata are visible to DuckDuckGo. These rows are available only after the corresponding optional browser permission is granted.

Optional outbound automations

An automation may include an httpRequest operation. The automation author chooses a static HTTPS destination, or an exact local loopback HTTP destination, plus the method, header names, body, and response mapping. Interpolated header values or body fields may contain credentials, page text, URLs, user-entered values, or earlier step results.

Before the request runs, Monocle validates the document, displays its network shape during review/import, checks a concrete host permission, and applies Firefox data consent where required. Requests omit ambient browser cookies and referrers, do not follow redirects or retry, do not run in private windows, and cap request and response bodies at 64 KiB. The destination provider's privacy and retention terms apply after receipt.

Optional OpenAI draft generation

If the user enables automation generation, Monocle sends the user's prompt, bundled authoring instructions/examples, and local snippet names and ids to OpenAI. It does not send snippet bodies or saved automation documents as generation context. The request uses the user's own API key, stored in the local extension profile, and sets store: false. OpenAI's terms and privacy policy apply to the request.

Optional Native Bridge

Native Bridge connects Monocle to a separately installed application on the same device. Once enabled and paired, it may send the active tab's URL and title, palette query text, command ids, and command results outside the extension/browser boundary to that local application. Incognito tabs are excluded. Pairing is per client and revocable; command execution requires a second opt-in and excludes confirm-gated, automation, and debug commands.

Optional peer-extension commands

Another browser extension may announce declarative commands to Monocle. Nothing is accepted until the user approves the browser-verified extension id. When an approved peer command runs, Monocle sends that peer the user's selection or form values for that command. Monocle does not send the peer the current tab URL or page content. Approval can be revoked.

Page SDK

A web page can register session-only commands through window.Monocle. Descriptors are schema-validated, carry no browser permission, and disappear with the page session. The page keeps and runs its own callback; Monocle does not upload it or evaluate it in extension context.

Keyboard and page access

The content overlay listens for registered Monocle keybindings. It ignores ordinary typing unless a key matches a configured binding or sequence prefix. Workflows may read or change page content only when the user runs them or when an enabled automation trigger fires. Baseline page content is not sent to a Monocle server because no such server exists.

This website

The marketing site is static and contains no Monocle analytics or account system. It currently loads Geist and Geist Mono from Google Fonts, so the browser makes a request to Google and shares ordinary network metadata. The website host may also keep standard access logs under its own terms.

Choices and deletion

Users can leave optional permissions ungranted, disable optional features, revoke paired clients and peer extensions, replace or remove the OpenAI API key, delete stored automations/snippets, clear extension storage, or uninstall Monocle. Browser permission controls remain authoritative.

Limited use

Data obtained through browser APIs is used only to provide or improve the user-facing Monocle feature that requested it. It is not transferred for advertising, credit-worthiness, sale, or unrelated profiling. Optional transfers occur only for the user-selected integration described above.

Changes and contact

Material changes will update the effective date and the public source. Questions and privacy requests can be opened in the public issue tracker → Do not include secrets, API keys, or private page content in a public issue.

Privacy starts with naming the boundary.
