Single purpose

Monocle is a command palette for the browser. It exposes the same command system through a page overlay and an optional new-tab replacement. Tabs, browser data, settings, snippets, calculations, automations, and approved integrations all remain commands inside that one keyboard-driven interface.

Permission model

The required set supports the palette, local state, content execution, and schedules. Sensitive browser APIs and broad hosts are optional, requested from a user action, and rechecked immediately before use.

Required at install

activeTab
Act on the tab the user is currently addressing.
scripting
Run extension-owned content workflows and support the page overlay.
storage
Store settings, favorites, keybindings, snippets, automation documents, and feature state in the local browser profile.
alarms
Run schedule, interval, and startup automation triggers and time-bound feature sessions.
contextualIdentities
Firefox only: support Multi-Account Container commands.

Optional API permissions

bookmarks · history
Search and open data from those browser collections.
tabs · sessions
Query tabs across windows and restore recently closed tabs or windows.
downloads
List downloads and reveal downloaded files.
cookies · browsingData
Run explicit clearing commands and Firefox container-aware operations.
management
List, enable, disable, or uninstall extensions. This high-scrutiny permission is requested only from extension-management commands.
nativeMessaging
Enable the separately installed Native Bridge. The bridge remains off until the user enables it and grants this permission.
tabGroups
Chrome only: use the native tab-groups API.

Execution enforcement

Permission prompts are user-initiated. Before protected work, the background checks the browser's current permission state again; revocation blocks execution even if a UI cache is stale.

Site SDK and remote-code posture

Pages may contribute declarative, session-only commands. They do not gain extension permissions and Monocle does not evaluate page-supplied code.

  • Page callbacks remain in page memory and cross the boundary only as callback ids.
  • On execution, Monocle sends the id back and the page runs its own callback in its own world.
  • Registrations are top-frame only, schema-validated twice, capped at 20 registrations, 100 commands, and five levels, and cleared with the page session.
  • SDK commands cannot request browser permissions or bind custom global keybindings.
  • The palette uses a closed shadow root, limiting page inspection of extension UI and browser-derived rows.
External extension messaging is separate

Chrome declares externally_connectable: { ids: ["*"] } so peer extensions can announce themselves. The browser-verified sender id must still be explicitly approved by the user before its declarative commands are accepted. Web pages are not listed as externally connectable origins.

Data handling by boundary

“No telemetry” is accurate. “Nothing leaves the device” is not.

Baseline

Settings, usage ranking, snippets, automations, and feature state are stored in storage.local. There is no Monocle account, analytics collector, advertising SDK, or Monocle-operated cloud.

Outbound automation

A user-authored httpRequest can send configured headers, body values, page-derived data, or credentials to a static HTTPS or exact-loopback endpoint after host permission and consent checks.

OpenAI draft generation

Optional generation sends the user's prompt, bundled automation context/examples, and snippet names/ids—not snippet bodies or saved automations—using a locally stored user API key and store: false.

Local integrations

Native Bridge can send active-tab URL/title, palette queries, command ids, and results to a paired local application. Approved peer extensions receive only the selection or form values supplied to their own command, not tab URL or page content.

Validation and executable-code boundaries

  • UI-to-background messages use typed message names, sender checks, and Zod payload schemas.
  • Automation documents are validated on save/import, at the message boundary, and again when run.
  • The workflow vocabulary is a closed set of bundled operations; unsupported steps fail.
  • There is no automation JavaScript step, eval, new Function, or remotely hosted executable code.
  • Calculation evaluation disables mathjs injection functions.
  • Clipboard access is write-only.

What a reviewer should test

  1. Baseline paletteOpen the overlay on an ordinary web page and the new-tab page; search and run an unpermissioned command.
  2. Permission grant and revocationRun a bookmarks/history command, deny or revoke the optional permission, and confirm execution is blocked.
  3. Site SDK fixtureUse the repository fixture page to register a declarative command and confirm it executes in the page, not the extension.
  4. Outbound automation disclosureInspect an automation containing httpRequest; verify its method, endpoint, and header names appear before consent and execution.
  5. Integration defaultsConfirm Native Bridge, peer-extension approval, remote command execution, and OpenAI generation are all disabled until separately enabled.
